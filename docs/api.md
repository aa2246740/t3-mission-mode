# HUD and Mission tool reference

Generated by `npm run docs:generate` from the route catalog and the actual MCP tool schemas. Run `npm run docs:check` to detect drift.

The HUD listens on loopback by default. Standalone QA needs no credentials and supplies no provider transport. Bind a Mission only in its owning T3 thread; a 200 response or a healthy HUD does not prove provider execution.

Cross-origin requests and foreign Host headers are refused. Commands accept JSON objects up to 1 MiB. `X-Request-ID` is echoed for diagnostics. SSE events contain Mission snapshots; keep this listener private.

The machine-readable contract is [openapi.json](openapi.json). Lifecycle-specific payloads still obey the kernel gates; arbitrary extra JSON properties confer no authority.

## MCP lifecycle tools

| Tool                              | Purpose                                                                                                                                                                                                                                              |
| --------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ReconcileBoundedTimer`           | Record original enable and current disabled receipts for one interrupted bounded timer without scheduling or dispatching work.                                                                                                                       |
| `MissionTick`                     | Advance approved Mission state deterministically and return exactly one owner action. Submit the original T3 responses as observations; never dispatch or End outside this loop.                                                                     |
| `ProposeMission`                  | Propose a new Mission plan with milestones, features, validation contract assertions (VAL-*), and 3-role model settings (orchestrator, worker, validator). Requires explicit user approval before execution.                                         |
| `ApproveMissionPlan`              | Record explicit user approval of the proposed Mission plan in the Mission HUD, unlocking StartMissionRun.                                                                                                                                            |
| `BindFeatureDispatch`             | Record an already accepted T3 task for the exact active run without dispatching, resuming or changing paused status. The caller must verify the task receipt against T3 before binding.                                                              |
| `StartMissionRun`                 | Start or resume the Mission execution loop. When resuming from a paused state with an activeWorker, checks the Git tree and wakes up the original childThreadId via t3_thread_send; otherwise dispatches the next pending feature via delegate_task. |
| `DismissHandoffItems`             | Dismiss or acknowledge worker handoff attention items (discovered issues or left-undone items) with explicit justifications.                                                                                                                         |
| `EndFeatureRun`                   | Complete an active Worker or Validator run with a structured handoff, updating feature status, validation assertions, and milestone validation injection.                                                                                            |
| `UpdateMissionFeatures`           | Add, update, or reorder features, milestones, validation assertions, modelSettings, or bonusAttempts in .mission/features.json and .mission/state.json.                                                                                              |
| `CheckMissionStateBeforeResuming` | Inspect .mission/state.json and check the Git working tree before resuming an interrupted or paused Mission.                                                                                                                                         |
| `WaitForApproval`                 | Block and poll .mission/state.json and .mission/progress_log.jsonl until the user approves or rejects the proposed Mission plan in the HUD.                                                                                                          |
